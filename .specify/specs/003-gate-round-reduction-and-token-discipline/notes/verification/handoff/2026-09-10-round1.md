## Traps this round proved are real

- **A round-2 report with ANY line before its `## Round 2` heading used to
  corrupt round 1.** `vf_reports` ignored prose outside a round while
  `vf_report_block` attributed it to the preceding round, silently changing a
  sealed digest and then wedging every later reserve/complete/probe with no
  scripted recovery. T030o11 closes it two ways, because the first way was not
  enough: fenced and blockquoted lines are *skipped* by report validation yet
  still absorbed by the accumulator, so only the pre-publish digest check
  catches those. Keep the returned report starting exactly at its heading.
- **`vf_report_block` accumulation was deliberately NOT changed.** Changing it
  could alter already-sealed digests, round 1's included. If you ever need to,
  verify `vf_report_block ../../opponent.md 1` still hashes to `1ac95178…`.
- **The gate report schema is now strict enough to refuse a sloppy report.**
  Required sections must exist, carry a non-blank non-heading body, and sit
  before the completion marker; every canonical finding needs `Wrong behavior`
  and `Class-wide fix`; and `Status: resolved` needs either an earlier round
  carrying that ID or an explicit `Prior`. A returned report that misses any of
  these cannot be completed — that is intended, but it means you may have to ask
  the agent for a corrected report rather than hand-editing gate state.
- **Config scalars now reject backticks and word-initial tilde** as well as
  every dollar form. Brace expansion and a literal `grep -c '^ok$'` end anchor
  stay legal, and there are positives pinning that.
- **A comma-less `FM-`/`INV-`-prefixed line is prose, not a mapping.** This
  reversed a T030o1 assertion; see the Decisions log for why no rule can
  separate the two. A required row lost that way is refused as
  `truncated-envelope`; a well-formed extra row is still refused as an extra.
- **Rejection classes are now typed and load-bearing.** `binding-mismatch` means
  only a genuine required-row problem, which is what the AC-016 probe demands.
  `truncated-envelope`, `forged-summary`, `wrong-task`, `capture-integrity`,
  `stale-capture`, `malformed-return` and `other` all fail that control.
- **Run library functions under `bash`, never the interactive zsh.** `vf_meta_load`
  and `vf_floor_validate` both "fail" under zsh because `read -d ''` and Bash
  arrays do not work there. Two diagnostics were wasted on that; the functions
  are correct.
